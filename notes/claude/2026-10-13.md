## How the work is done

These are the user's standing preferences and the procedures that worked.
Most are also in Claude's memory for this project; this note is the backup.

**Writing.** American English ("math"). No dashes as sentence punctuation:
use a separate sentence, a colon, a comma or parentheses, or a spaced
" - " if a dash is really needed. Hyphens in compound modifiers are fine.
This applies to replies, commit messages, PR descriptions, notes and the
port page.

**PRs and merges.**

- One PR per piece of work. Merge only when the user asks, with
  `gh pr merge N --rebase --delete-branch`.
- Docs-only commits go straight to the default branch with `[skip ci]`.
- An engine change is two PRs: rr-python first, then rr with the rebuilt
  engine. Merge rr-python first. Then amend the rr commit message and PR
  description to cite rr-python's merged master hash. Take both hashes from
  git, check the rewritten message before pushing, then merge rr.
- A PR stacked on another: retarget it to the default branch before the
  base branch is deleted, or GitHub closes it.
- Play an audible signal when a step is done:
  `afplay /System/Library/Sounds/Glass.aiff; say "..."`.

**Checking a fix.** Run the new test on the code before the fix too, and say
whether it failed there. Compare against a baseline from before all of
Claude's changes, not just the latest. Report measured results, not guesses.

## rr-python: building and testing on this Mac

Full notes: `rr-python/rr-python/notes/native-tests-macos.md` and
`notes/wasm-build-310.txt`.

- **Native CPython** is built out of tree in
  `python-3.10.19/build-native`, installed to `install-3.10.19`. Its
  `Modules/Setup.local` is the source one plus `*disabled*` / `_heapq`. The
  C++ compiler is `NoStack_ST_310/macos/cxx-no-c99`, which drops `-std=c99`
  so abb builds.
- **After changing a CPython `.c` file:**
  `cd python-3.10.19/build-native && make -j8 libpython3.10d.a`.
- **After changing a file in `rr-python/py/`:** `cd rr-python/py && bash
  install-310.sh`. It copies to both the native and the emscripten installs.
- **Native tests:** `cd rr-python/NoStack_ST_310 && make -f Makefile.macos
  run` runs every suite. `SUITES="simple rr"` runs some, and a test name
  runs one test. Runs overwrite the tracked `*-stdout.txt` files.
- **Run one test with a time limit**, since a hang otherwise blocks the
  shell: start `NoS-macos` in the background and kill it after 30 s.
- **`NoStack_ST/main.c` has CRLF line endings.** Edit it in binary mode, or
  the whole file shows as changed.
- **Never change a CPython header** (`Include/`). It forces every object to
  rebuild, and the emscripten build's abb C++ objects have not been rebuilt
  on this Mac. New operation codes were defined in the `.c` files instead.
- **The wasm engine:** `source ~/dev/ai/emsdk/emsdk_env.sh`, then in
  `python-3.10.19/build-emscripten` run `emmake make libpython3.10d.a` and
  copy it to `../install-emscripten/lib/`. Then `cd
  rr-python/02_st_310 && make clean && make`. Copy `python.asm.wasm`,
  `rr-python.asm.js` and `python.asm.data` to `rr/public/rr-python/`.
- **Engine builds are not byte-reproducible:** CPython stamps the build
  time. To decide whether rr needs a rebuild, compare rr's three files with
  `02_st_310`'s, and the repo's `py/` files with `install-emscripten`'s.
  `make -n` reporting `ceval.o` after a merge usually means only that the
  merge rewrote the file on disk.
- **A worker abort looks like a hang** in rr's Playwright probes. Capture
  the page console and look for "Assertion".
- **The engine's own debug output** goes through redirected stdout. In
  storable3.py, write probes to fd 2 (`os.write(2, ...)`).

## rr: testing

- rr's engine specs, about 50 s together:
  `npx playwright test tests/pe-statements.spec.ts tests/pe-world-calls.spec.ts
  tests/pe-storables.spec.ts tests/pe-library-calls.spec.ts
  tests/pe-imports.spec.ts tests/measure-python.spec.ts
  tests/vision-fixture-python.spec.ts`
- They need Chrome (`test.use({ channel: 'chrome' })`): Playwright's
  headless shell is missing on this machine.
- Probing the engine from a spec: import `/src/app/pe/python-engine.ts` in
  `page.evaluate`, `new PythonEngine()`, `setCallbacks`, `initialize()`,
  `parse(src, 'main', 8000, 0n, 8000, 8000n)`, `compile`, then `step()` or
  `run()`. A world call returns status `world-call`; answer it with
  `run({ worlds: JSON.stringify({ reqId, status, ... }) })`.
- Editing rr's sources during a Playwright run makes Vite reload the page.
